# Compositor placement research

## v1 decision and evidence boundary

The v1 compositor target is **Hyprland only**. Niri is post-v1 and unverified. The placement and output-selection measurements below were made on Hyprland `0.56.2`, GTK `4.22.5`, gtk4-layer-shell `1.3.0`, Go `go1.27.1-X:nodwarf5 linux/amd64`, Linux `7.3.0-rc3-1-cachyos-rc`, with the isolated gotk4 `v0.4.1` probe. This is the tested version tuple, not a claim that all Hyprland `0.56.2` use cases are complete or that lower/later versions work. The probe is a nested research module; the production overlay remains owned by Issue #32.

For v1, use overlay layer, production namespace `azerlay`, keyboard mode none, exclusive zone `-1`, nine configured anchors, and signed X/Y margins. On a centered axis, positive margins move right/down and negative margins move left/up. The existing `overlay.monitor` remains an opaque string: empty delegates output choice to the compositor; a nonempty value selects an exact connector first or, if no connector matches, a unique exact GDK description. Missing or ambiguous explicit selection keeps the overlay hidden. When its selected output disappears, keep input/configuration state and hide the overlay without migration; show it only after the same configured key uniquely resolves again. A matching key is not a permanent physical monitor identity.

The live headless-output removal test demonstrated hiding, but **same-key headless return failed to produce a verified restored overlay**: after the output was recreated, the probe aborted on a GDK scale assertion and Hyprland dumped core. A later isolated nested session did restore the same probe on a Wayland-backed virtual output; that narrower result does not resolve the headless failure. The criterion remains open. The local `.omo/evidence` paths below identify run artifacts; the commands, measured values, and verdicts are reproduced in this decision so that its conclusions remain readable without those ignored files.

## Monitor identity (Issue #41, Todo 3; 2026-09-23)

The existing opaque `overlay.monitor` value uses this v1 selection policy: an empty value delegates output choice to the compositor (`default` in the probe); a nonempty value first matches an exact GDK connector, then a unique exact GDK description. A missing or ambiguous explicit match stays hidden. An explicit output's removal must hide the overlay while retaining state, with no migration to another output. Reappearance means the same configured key uniquely resolves again. Connector names can be renumbered or reused and descriptions are not proven permanent hardware identifiers, so a same-key return is not proof that the same physical device returned. The tested GDK accessor set exposes connector, description, manufacturer, and model but no proven persistent physical ID. No new config field is selected.

The live GDK preflight used `/usr/bin/python3` with GTK 4 initialization and `Gdk.Display.get_default().get_monitors()`. It found two monitors, one exact `DP-2` connector and one exact match for that monitor's description; only counts and availability were written to `.omo/evidence/probe-todo3/gdk-selector-preflight.log`. A `hyprctl monitors -j` projection recorded only connector names and description availability in `.omo/evidence/probe-todo3/hyprland-monitors.json`. The raw description, which may include a serial, stayed in memory. For the description run, the shell set `AZERLAY_TARGET_DESCRIPTION` from the GDK DP-2 monitor and passed `"$AZERLAY_TARGET_DESCRIPTION"` as one quoted probe argument; the transcript records that variable reference, not its value.

Each observed selector run used `env XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-1 GDK_BACKEND=wayland GSK_RENDERER=cairo G_DEBUG=fatal-warnings /tmp/azerlay-placement-probe --placement bottom-right 24 24 MONITOR -1` in an interactive `script -q -f -e -c` session. `MONITOR` was `default`, `DP-2`, the in-memory GDK description, or `DOES-NOT-EXIST` as indicated below. While the probe was mapped or waiting, `hyprctl layers -j` was filtered to namespace `azerlay-placement-probe` across all outputs. The local Wayland socket, Hyprland session identifier, and temporary binary path describe this observation, not required product settings.

## Output lifecycle (Issue #41, Todo 4; 2026-09-23)

This was a software-created Hyprland headless output, not a physical cable unplug. The tested binary was Hyprland `0.56.2` with GTK `4.22.5`, gtk4-layer-shell `1.3.0`, Go `1.27.1-X:nodwarf5`, and Linux `7.3.0-rc3-1-cachyos-rc`. The output was named `azerlay-probe`; the existing DP-1 and DP-2 outputs were not configured by this run. The interactive probe invocation was `env XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-1 GDK_BACKEND=wayland GSK_RENDERER=cairo G_DEBUG=fatal-warnings /tmp/azerlay-placement-probe --placement bottom-right 24 24 azerlay-probe -1`, followed by `status`, `hide`, `show`, `recreate`, and another `status` across the phases below. Its transcript is `.omo/evidence/probe-todo4/lifecycle.typescript`.

The preflight `hyprctl monitors -j` contained only DP-1 and DP-2 (`preflight-monitors.json`). `hyprctl output create headless azerlay-probe` returned `ok` (`create.log`). An attempted `hyprctl keyword monitor azerlay-probe,1920x1080@60,auto,1.25` returned process exit 0 **but reported** `keyword can't work with non-legacy parsers. Use eval.` (`configure.log`); that exit code did not configure the output. A subsequent `hyprctl eval` call returned `ok` (`configure-eval.log`), and `hyprctl monitors -j` independently confirmed `azerlay-probe` at `(4480,0)`, reported mode `1920×1080`, scale `1.25` (`configured-monitors.json`). The exact Lua argument to `eval` was not retained in the evidence, so only the observed command result and monitor state are asserted. GDK independently reported logical bounds `(4480,0,1536,864)` at scale `1.25` (`gdk-geometry.log`); the `1920×1080` Hyprland mode is not the GDK logical size.

The observed layer coordinate follows the logical bounds: `x=4480+1536-160-24=5832`, `y=864-80-24=760`. DP-1 and DP-2 retained scale `1` and `reserved=[0,44,0,0]` in the captured preflight, configured, and removed monitor snapshots. The removal observation demonstrates the probe's explicit-selector policy. It does not show what an unguarded gtk4-layer-shell window would do on monitor invalidation. The planned v1 production behavior remains hidden with state retained until the configured key uniquely resolves again; the return path is unverified and this Issue remains open.

Post-crash inspection of the host core (Hyprland PID 2095) found `SIGFPE/FPE_INTDIV` at `CHeadlessOutput::scheduleFrame` with the `idiv %rcx` divisor register equal to `0`. The installed Aquamarine `0.15.1` source divides the frame interval by the active mode's refresh rate without checking for zero ([Headless.cpp](https://github.com/hyprwm/aquamarine/blob/f31c47a1b9d300847d8fc3108ad959448103dfc1/src/backend/Headless.cpp#L80-L89)); Hyprland `0.56.2` calls it while applying the monitor rule ([Monitor.cpp](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/output/Monitor.cpp#L1048-L1056)). Hyprland has a non-DRM fallback that can set a custom mode with refresh rate zero when candidate modes fail ([Monitor.cpp](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/output/Monitor.cpp#L919-L937)), but the core and retained logs do not establish why the normal 60 Hz headless mode was not used on this return. The probe's earlier `SIGABRT` was caused by the test invocation's `G_DEBUG=fatal-warnings` turning GDK's `gdk_monitor_set_scale` warning into an abort; that warning still indicates an invalid transient monitor scale, and removing the flag would not prevent the compositor's zero division. Neither crash identifies a proven defect in the probe's monitor-selection code.

The installed Aquamarine `0.15.1` and the inspected upstream source still have this unguarded division. Until the zero-refresh path is resolved and validated in isolation, repeating the headless remove/recreate sequence on the host session risks another compositor crash. The nested Wayland-backed output test below is the safe real-compositor observation for same-key reattachment; it does not fulfill the headless return criterion.

A post-crash control run on the restarted live host used a freshly built probe with `G_DEBUG` unset and explicit `DP-2`: it mapped on `DP-2`, reported an empty input region, answered `status`, and exited 0 on `quit`. A subsequent `hyprctl monitors -j` still showed DP-1 and DP-2 at their original modes, `hyprctl layers -j` showed no remaining probe layer, and no new Hyprland/probe core appeared. This checks the stable-output probe path; it does not exercise output removal or return.

After the crash, the restarted Hyprland `0.56.2` session reported only DP-1 and DP-2, both scale `1`, `reserved=[0,44,0,0]`, with zero `azerlay-placement-probe` layers. `pgrep -af '^/tmp/azerlay-placement-probe'` found no running probe (`.omo/evidence/probe-todo4/aftermath.md`). This is a cleanup observation, not evidence that same-key return succeeded. No physical hotplug, lower or later Hyprland version, or persistent physical-output identity was tested.

### Isolated same-key retry on a nested Wayland output (2026-09-23)

A separate Hyprland `0.56.2` instance ran nested on the host Wayland socket with a minimal Lua config; its own socket was `wayland-2` and its existing output was `WAYLAND-1`. The host DP-1 and DP-2 were not configured. The nested `hyprctl output create headless azerlay-probe` and `hyprctl eval 'hl.monitor({ output = "azerlay-probe", mode = "1920x1080@60", position = "auto", scale = 1.25 })'` both returned `ok`, but `hyprctl monitors -j` reported that output as `0×0`, scale `1`. Aquamarine repeatedly reported GBM buffer allocation failure. Restarting the nested instance with `LIBGL_ALWAYS_SOFTWARE=1` produced the same result. No probe was run against this unusable headless output.

In that second nested instance, `hyprctl output create wayland azerlay-probe` instead produced an active output. The same Lua monitor rule yielded mode `1920×1080`, scale `1.25`, at `(1900,0)`. The unchanged probe ran on the nested `wayland-2` socket as `/tmp/azerlay-issue41-isolated-probe --placement bottom-right 24 24 azerlay-probe -1`. Its status reported `resolution=connector mapped=true actual=connector="azerlay-probe"`; `hyprctl layers -j` placed its `160×80` layer on `azerlay-probe` at `(3252,760)`, consistent with the output's `1536×864` logical size and `(24,24)` margins.

| Phase | Probe status and compositor observation | Verdict |
| --- | --- | --- |
| `hyprctl output remove azerlay-probe` with the probe running | The same probe process reported `resolution=missing selector mapped=false actual=none`; only `WAYLAND-1` remained and no `azerlay-placement-probe` layer was present | Hide without migration observed |

This shows that the probe can reattach on one isolated Wayland-backed output cycle. The different compositor instance and output backend do not isolate the cause of the host-session crash. The host-session headless crash and the nested headless `0×0` setup failure keep the planned headless return criterion open; physical connector return is also unverified.

### Handoff to Issue #32

The production bridge should implement the selected v1 contract on GTK's locked main OS thread: initialize gtk4-layer-shell with namespace `azerlay`, overlay layer, keyboard mode none, nine-anchor/margin mapping, exclusive zone `-1`, and an empty GDK input region on every mapped surface. The probe's `azerlay-placement-probe` namespace and fixed `160×80` surface are research fixtures, not production settings. Avoid changing the root Go module dependency boundary solely for this decision.

Resolve the configured output from the current GDK monitor list using connector-first/unique-description selection. For an unresolved explicit key, keep the overlay unmapped while the reducer's input/configuration state continues; do not migrate to the compositor's default output. Re-evaluate on monitor-list changes and show only when the same key uniquely resolves. Disconnect handlers for invalid surfaces and reapply the empty input region after each actual map. No new `overlay.monitor` field or persistent hardware identifier is defined.

The headless same-key return remains a blocking validation gap for that implementation despite the nested Wayland-backed success. Reproduce and resolve the GDK/Hyprland headless path in a controlled environment before claiming general return recovery, and separately validate compositor-originated remap and physical hotplug if required for release. The prior [ABI decision](overlay-abi.md) remains the authority for GTK pointer ownership and click-through observations; these placement measurements do not replace it.
