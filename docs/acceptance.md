# Azerlay 1.0 acceptance evidence

The acceptance criteria remain defined in [System design and research](design-research.md#28-受入条件). This table records the evidence currently available for each criterion; it does not change the criteria or imply that the product is release-ready.

Evidence labels distinguish **coverage** (tracked tests or CI configuration),
**historical observation** (a recorded run), and **CI execution** (a completed
run at a named source revision). Test definitions are not presented as a run.
No product test was run as part of this documentation change.

| Status | Meaning |
| --- | --- |
| Verified | Available evidence meets the criterion within the stated scope and limits. |
| Partial | Some required behavior has evidence, but the full criterion is not established. |
| Unverified | The required outcome has no direct qualifying evidence. |
| Deferred | The criterion explicitly defers the behavior beyond v1. |
| Blocked | An identified release blocker prevents completion of the criterion. |

## Scope notes

- The version-unknown str16 observation and synthetic empty-bundle test for AC-001 are distinct from the owner-attributed Software 2.0.2 str32 bundle with 43 inputs.
- The AC-007 GTK receiver run does not prove delivery to a real game. `input_region_applied` only records the GTK call.
- AC-008 has no real-game input A/B result. AC-014 has no runtime network capture.
- AC-015's native library, Layer Shell and monitor checks are still absent. AC-016's release blocker remains open.
- Issue #132 research is nonblocking post-v1 work. The analog criterion AC-010 is deferred. Niri, Ubuntu and right-hand Cyborg II remain outside v1 as listed in the [compatibility matrix](compatibility.md).
